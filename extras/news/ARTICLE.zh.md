## 🌟 六大核心升级 (Core Upgrades)

### 1. AI 智能研判引擎 (AI-Powered Analysis)

这是本次更新的灵魂。

V1 的板块分析依赖一份写死的"利好/利空"词表：看到 `surge` 加一分，看到 `slump` 减一分。这种做法有个致命问题——**它不懂语义**。一条"美联储降息预期落空，科技股承压"的新闻，因为包含 `cut`（降息）这个"利空词"而被正确扣分纯属巧合；而"英伟达财报超预期但股价下跌"这种复杂表述，词袋法完全无能为力。

V2 接入 **Google Gemini**，把 100 条全球财经头条一次性喂给大模型，让它输出结构化的板块研判：

```
{
  "summary_en": "...",
  "summary_zh": "...",
  "sectors": [
    { "name": "Technology", "trend": "BULLISH", "reason_en": "...", "reason_zh": "..." }
  ]
}
```

**关键设计：优雅降级 (Graceful Degradation)。**

AI 不是银弹——它可能超时、可能限流、可能返回不合法的 JSON。所以 V2 采用双引擎架构：

```
AI 分析成功 → 使用 AI 结果，邮件标题标记 [AI]
AI 分析失败 → 自动回退到 V1 的关键词算法，邮件照常送达
```

**你的简报永远不会因为 AI 挂了而收不到。** 邮件顶部的徽章会明确告诉你今天用的是哪套引擎：

- 🤖 `AI-POWERED ANALYSIS / AI 智能分析`
- 📊 `KEYWORD ANALYSIS / 关键词分析(AI 不可用)`

### 2. 智能去重系统 (Smart Deduplication)

V1 最影响体验的问题：**同一条新闻连续推送好几天**。

因为 NewsAPI 的 `sortBy=popularity` 会把热门老闻反复捞出来，而免费版数据本身就有约 24 小时延迟。

V2 的解法分三层：

- **时间窗口收紧**：请求时带上 `from=昨天`，从源头切断陈年旧闻
- **URL 指纹去重**：剥离 `?utm_source=xxx` 这类追踪参数后再比对，避免同一篇文章因链接后缀不同被判定为新内容
- **3 天滑动窗口**：已推送记录存 3 天后自动清理

特别说一下存储方案。GAS 的脚本属性有数量上限，V2 没有用"一条 URL 一个属性"的粗暴做法，而是把整张去重表序列化成**单个 JSON 属性**，配合过期清理，**容量恒定不膨胀**，跑一年也不会撑爆。

### 3. 反垃圾内容过滤 (Anti-Spam Filtering)

不少读者反馈简报里混进了"黑五好物推荐""限时折扣"这类电商软文——它们确实带着 `business` 标签，但毫无情报价值。

V2 建立了三道防线：

- **查询层**：搜索词直接加上 `NOT (promo OR coupon OR gift OR deal OR "sponsored post")`
- **文本黑名单**：命中 `gift guide`、`free shipping`、`shop now`、`save $` 等 11 个促销特征词即丢弃
- **媒体源黑名单**：屏蔽 YouTube、Daily Mail、PR Newswire 等低信噪比来源

> 一个容易踩的坑：媒体源黑名单必须匹配 `source.name` 字段，而不是正文。否则一篇正常报道只要提了一句"据每日邮报"就会被误杀。V2 已做了字段隔离。

同时保留了基础质量门槛：标题少于 15 字符、摘要少于 20 字符、内容为 `[Removed]` 的条目一律过滤。

### 4. 订阅制多人分发 (Multi-Recipient Broadcasting)

现在你可以把这份简报分享给同事、朋友、投资群了。

在脚本属性里配置 `RECIPIENTS`，支持逗号、分号、换行三种分隔符：

```
alice@example.com, bob@example.com
charlie@example.com
```

**隐私保护设计**：所有者放 `to`，其余订阅者一律走 **BCC**。订阅者之间互相看不到对方邮箱——这是发送多人邮件最基本的职业素养。

系统还会做邮箱格式校验，非法地址跳过并记日志，不会因为一个手滑打错的地址导致整封邮件发送失败。

### 5. 生产级容错 (Production-Grade Resilience)

V1 跑挂了你是不知道的——GAS 静默失败，你只会觉得"今天怎么没收到邮件"。

V2 补齐了完整的可观测性：

- **失败告警**：任何环节抛异常，立刻给所有者发一封带完整堆栈的 `[Market Report] Script FAILED`
- **触发器通知**：异常捕获后 `rethrow`，让 Google 官方的触发器失败通知也能生效（双保险）
- **空结果通知**：如果当天所有文章都被过滤或已推送过，**只通知所有者**，不打扰订阅者
- **翻译降级**：`LanguageApp` 翻译失败时降级为空串，邮件照发，只是少了中文，不会因为一条翻译失败毁掉整封简报
- **事务性写入**：去重记录在**邮件发送成功之后**才批量落盘——避免"记录写了但邮件没发出去"导致新闻永久丢失

### 6. 安全加固 (Security Hardening)

- **密钥外置**：`NEWS_API_KEY` 和 `GEMINI_API_KEY` 全部迁移到脚本属性。**代码可以随便截图、随便分享，不会泄露密钥**——这也是我这次敢把完整代码贴出来的前提
- **XSS 防护**：所有来自外部 API 的内容（标题、摘要、URL）全部经过 HTML 转义。新闻标题里出现 `<script>` 也只会被当成纯文本显示
- **Gemini Key 走 Header**：改用 `x-goog-api-key` 请求头传递，避免密钥出现在 URL 里被日志记录

## 🛠️ 老用户迁移指南 (Migration Guide)

已经部署了 V1 的朋友，三步完成升级：

### 第一步：备份并替换代码

1. 打开你的 Apps Script 项目
2. **先把 V1 代码里的 API Key 复制出来存好**
3. 全选删除，粘贴仓库里的 `news.js`（另建一个 `MM_util` 文件粘贴 `MM_util.js`）

### 第二步：配置脚本属性

点击左侧 **⚙️ 项目设置 (Project Settings)** → 滚动到底部 **脚本属性 (Script Properties)** → 添加属性：

| 属性名 | 值 | 是否必填 |
|---|---|---|
| `NEWS_API_KEY` | 你的 NewsAPI 密钥 | ✅ 必填 |
| `GEMINI_API_KEY` | 你的 Gemini 密钥 | 选填，不填则退化为关键词分析 |
| `RECIPIENTS` | 订阅者邮箱，逗号分隔 | 选填，不填则只发自己 |

> Gemini API Key 在 Google AI Studio 免费申请，个人使用额度完全够用。

### 第三步：验证

1. 先运行 `MM_probe()`（会议纪要系统自带），看 `[V4b]` 行为 ✅，说明 AI 通道打通；没装 MM 的话直接跳到第 2 步
2. 再手动运行 `sendEnglishPrimaryBilingualReport()`
3. 检查收到的邮件顶部是否显示 🤖 `AI-POWERED ANALYSIS` 徽章

**触发器无需改动**，函数名保持不变。

## 🆕 新用户完整部署 (Fresh Deployment)

### 第一步：获取两把钥匙

1. 前往 **NewsAPI.org** 注册，获取 API Key
2. 前往 **Google AI Studio** 获取 Gemini API Key（可选，但强烈建议）

### 第二步：创建项目

1. 登录 **Google Apps Script**，新建项目
2. 删除默认代码，粘贴仓库里的 `news.js` 与 `MM_util.js`
3. 按上文"第二步"配置脚本属性
4. 点击 Run 运行，完成授权（`Advanced` → `Go to ... (unsafe)` → `Allow`）

### 第三步：设置定时

1. 左侧 **Triggers**（闹钟图标）→ **Add Trigger**
2. 函数选 `sendEnglishPrimaryBilingualReport`
3. `Time-driven` → `Day timer` → `10am to 11am`
4. 在 **Project Settings** 中确认时区为 `(GMT+08:00) Beijing`

## ⚠️ 已知限制与诚实提示

写教程不能只讲好话，这几点你必须知道：

1. **NewsAPI 免费版有约 24 小时延迟**，且单页上限 100 条。它适合做"每日复盘"，**不适合做盘中交易决策**。
2. **AI 分析基于标题，不是全文**。为控制 token 消耗，脚本只把 100 条标题喂给模型。这意味着分析深度有限，**AI 也会出错、也会幻觉**。
3. **邮件发送有配额**：个人 Gmail 账号约 100 收件人/天，Workspace 约 1500/天。订阅者超过几十人时请留意。
4. **本系统输出不构成任何投资建议**。它的定位是"帮你节省每天筛选信息的 30 分钟"，而不是"帮你选股"。所有决策请自行判断。
5. **模型名称可能变化**。代码中的 Gemini 模型名请对照官方文档确认当前可用版本，模型下线会导致 AI 分析降级（但不影响邮件送达）。

## 💭 写在最后

V1 是一个"能跑的 Demo"，V2 才是一个"能长期跑的系统"。

这中间的差距，不在于加了多少炫酷功能，而在于处理了多少"不会发生但一定会发生"的边界情况：API 挂了怎么办、翻译失败怎么办、发送成功但记录没写怎么办、订阅者填错邮箱怎么办。

**这大概就是玩具和工具的分界线。**
