# 05 · 日常使用与常见问题

[English](05-daily-use.en.md) · **简体中文**

## 每场会的两个动作

1. **日历上接受邀请**。默认只处理「我组织的」和「我点了『是』的」会。「待定」和没回复的不处理（想处理的话把 `MM_EVENT_SCOPE` 改成 `all`）。
2. **让会议留下文字**，两种方式任选其一：
   - **建会时就打开**（推荐，不会忘）：日历新建 / 编辑事件 → 加上 Google Meet 后，下方出现「Use Gemini to take meeting notes / 让 Gemini 记会议笔记」开关，打开并保存。之后每次开会 Gemini 自动记笔记，结束后笔记 Doc 出现在 `Google Meet/` 文件夹，系统能直接读。
   - **会中手动开**：Meet 右上角的 Gemini 笔记图标 → 勾上「Also start transcription」→「Start taking notes」。任何一个参会人开都行，不一定是你。

   ![日历事件里的 Gemini 记笔记开关](images/04-invite-steve.png)

其他都不用管。会议结束后：

| 时间 | 发生什么 |
|---|---|
| 结束后 10~30 分钟 | Google 把转录 Doc 放进组织者的 Drive `Google Meet/`，参会人 Drive 里出现快捷方式 |
| 每 15 分钟一轮 | 系统发现转录 → 调 Gemini → 生成 Doc → 写行动项 → Jira 评论 → 发邮件，每轮走一步 |
| 通常 15~45 分钟 | 邮件到 |
| 最多 12 小时 | 还没等到转录 → 标记 EXPIRED，给部署者发一封告警 |

## 行动项：怎么关掉

纪要邮件里的行动项会写进后台表 `Actions` 标签页，每周一汇总一次还没关的。

**关掉一条**：打开后台表（`会议双语纪要系统 — 后台数据表`）→ `Actions` → 找到那一行 → `status` 列从 `OPEN` 改成：

- `DONE` —— 做完了
- `DROPPED` —— 不做了

也可以顺手在 `due` 列填截止日期（`2026-10-01` 这种格式），周一汇总就会按「7 天内到期或已过期」提醒，而不是「挂了两周就提醒」。

![Actions 标签页改 status 的那个单元格](images/05-actions-status.png)

**规则**：只有 `status` 恰好是 `OPEN`（不分大小写）的行才会进汇总。系统重跑同一场会时**不会**覆盖你改过的状态。没有待办时周一不发信。

用 Steve 实例的同事：告诉 Steve 哪条，或请他把表共享给你。

## 常见问题

### 没收到邮件

先查你自己能看到的几项，多数情况卡在前三条：

| # | 检查 | 怎么确认 |
|---|---|---|
| 1 | **会议留下文字了吗？** | 组织者的 Drive `Google Meet/` 里有没有这场会的 Gemini 笔记或转录 Doc。没有 = 两样都没开，无解 |
| 2 | **日历上回复的是「是」吗？** | 自己部署：你在那场会上点了「是」而不是「待定」。找 Steve 代跑：Steve 在受邀名单里并接受了 |
| 3 | **会有 Meet 链接吗？** | 用 Zoom / Teams / 电话的会不处理 |
| 4 | **还没到时间** | 转录本身要 10~30 分钟才出现，之后系统每 15 分钟走一步。结束 1 小时内先别急 |
| 5 | **你在收件人里吗？**（找 Steve 代跑时） | 默认只发 Steve。要自己收到，得让 Steve 把你加进订阅名单，见 [04 · S2](04-use-steve-instance.zh.md#s2--s3--我想收到自己参加的会的纪要) |
| 6 | **邮件进垃圾箱** | 搜主题 `[会议纪要]`。发件人是部署者本人：自己部署是你，代跑是 Steve |

以上都没问题，就轮到部署者查了（自己部署就是你，代跑就把会议标题和日期发给 Steve）：

| # | 检查 | 怎么确认 |
|---|---|---|
| 7 | **在处理范围内吗？** | 运行 `MM_calDump`，看 `eligible` 和 `reasons` |
| 8 | **月度熔断了** | 运行 `MM_status` 看「本月用量」；超过 1200 分钟当月停处理，部署者会收到告警 |
| 9 | **任务失败了** | 后台表 `Tasks` 找这场会，看 `status` 和 `last_error`。`FAILED` 常见原因：Gemini Key 失效、模型名下线。修好后用 `MM_retryTask` 重跑 |

### 收到了但内容不对

- **中文/英文只有一种**：另一种生成失败时降级为单语，邮件顶部会有黄色提示。重跑一次通常就好。
- **行动项负责人是空的**：转录里没说清谁负责。Meet 转录如果没有标注说话人（比如只开了 Gemini 笔记），AI 只能猜。
- **术语翻错**：AI 抽取，以会议原文为准。邮件底部有免责声明不是白写的。

### 别人组织的会，怎么让它处理

系统默认处理「我组织的 + 我已接受的」。别人组织的会，你只要在日历上点「是」就行。如果 `MM_calDump` 里 `reasons` 写「不在范围」，检查 `MM_EVENT_SCOPE`。

### 周期性会议

每次都是独立任务，每次都要开转录。日历改期系统会跟着改；取消的不处理也不告警。

### 会议改了时间

系统每 15 分钟核对一次日历，改期自动跟随，不用管。

### 转录是英文的，会有中文纪要吗

有。转录语言无所谓，输出永远按 `MM_LANG`（默认中英双语）。

### 中英混说的会，转录质量怎样

Meet 转录对混说的识别一般，专有名词和人名容易错。AI 在生成纪要时会做一定纠正，但不保证。重要数字和人名请核对原文。

### 我想停掉 / 卸载

- 暂停：编辑器运行 `MM_uninstall`，删掉两个定时任务，数据都保留。
- 恢复：再运行 `MM_setupOnce`。
- 彻底删除：删 Apps Script 项目、后台表格、`会议纪要（中文·私人）/` 和 `会议录音/` 文件夹。已生成的 Doc 是普通文件，要删自己删。

### 月度熔断到底是多少

默认每月 1200「分钟」。文本转录按 token 折算（约 292 token = 1 分钟），录音按真实时长。1 小时的会约占 50~70 分钟额度，所以默认额度大约够每月 20 场一小时的会。一个人自用通常够，会多就改 `MM_MAX_MONTHLY_MINUTES` 调高。

### 能不能不让它发邮件，只要 Doc

`MM_DELIVER = doc`。

### Doc 放到别的文件夹

`MM_ZH_FOLDER` 改名字。英文版想单独放：`MM_EN_FOLDER = 英文纪要`。想跟随会议目录：`MM_EN_FOLDER = meeting`。
